# First Prompt

> I want you to create a folder called docs in lowercase, and then inside that, let's create a markdown file called specs. I'm going to describe you what I want to build, and I want to first have this document created with the organization of the specs and some other notes, and we'll start building afterwards. We're going to build progressively a chatbot server. On the backend, I want to build a REST backend in Fast API that sits as a proxy between the chat client and the LLM. Therefore, the front end will never call the model directly. Fast API will receive the request, call the LLM over a open AI compatible API that will be pointing at a model through API keys or using a local model by configuration only. And then the backend will pass the answer back. Then for the front end, I want to build it with vanilla JavaScript, HTML, and CSS. It will be a chat window that will render the model's replies as markdown. So code blocks, lists, and headings will come out formatted instead of raw. We won't use any framework for JavaScript. I also want a way to visualize the context. This will show what is actually sent to the model and the token usage that comes back. The user should be able to see the conversation growing and the tokens climbing. When needed, it must be able to run from a Docker Compose app. That means that we need to build a Docker file for it to run, and also being able to run it locally. The user should edit a .env file, and the system must be served on ports like 666 something, for example 666.1 or 666.2. The configuration will live in the .env file. Configurations like base URL, the key, and the model. Let's make sure this file is never committed. So let's add it to the git ignore. Finally, we can talk about different stages that I want this to build in. So the first stage will be the baseline, which it won't use streaming yet. The fast API will call the LLM. It will wait for the whole answer, and then it will return it. The chat window will show it then when it arrives. The second stage is advanced, which will include streaming. In this one, Fast API will stream from the LLM and proxy that stream through the front end. We can use server sent events, and in this way the answer will type out token by token instead of landing all at once. This will be the proxy doing the real work, relaying a live stream, not just forwarding a finished blob. The third stage will be called best, and it will include vision. If the model is vision capable, we will let the user attach an image to a question so they can send it along with a query. The fourth stage will include chat history, where we will use SQLite for this. We don't have user accounts for now, but let's take into account that this can be implemented in the future. So for now, for the chat history, it can use a structure based on accounts, but we won't do any authentication yet. This may be like the whole system may be used by other people that will pull from the repository and then run Docker Compose up, edit that env file, and then being able to see and use the system. So let's also include instructions for this in a README file. And then for the design style, I have these three colors: 008790, FF7A5B, and FCCA67. They look well together, so let's use them and then shades of them, and please take a look at good ways to you know, use color tones in UI. And you know, find the call to action like primary, secondary, and shades, colors, more or less based on these three that I shared. And then I want a playful look and feel. We can also make it look like a 2D vector drawing, let's not use gradients, but instead let's use solid colors. Let's use, when needed, an effect of 3D, like for example for buttons, where we will render like a depth, but being done just by 2D flat style.
